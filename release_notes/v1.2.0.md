# Release Notes v1.2.0

This release overhauls map management and transfer reliability. Unsaved map changes now remain available as backend RAM drafts, while SPIFFS is only updated by an explicit Save action.

## Map Management

- Added per-map RAM drafts so unsaved edits survive browser reloads and switching between maps.
- Added reliable Create, Copy, Load, Save, and Revert workflows for managed maps.
- Save and Revert actions are now available in the main map toolbar, and the map selector uses a more compact layout.
- Revert atomically discards the current draft and reloads the persisted map, preventing races between separate discard and load requests.
- Switching maps cancels pending edit synchronization so delayed updates cannot modify or dirty the newly selected map.
- Save flushes pending edits in the correct order and no longer causes the map to become dirty again immediately afterward.
- Mowing-area switches are kept in the backend map draft and restored after a browser reload.
- Partial mowing-settings updates preserve flags that were not included in the request.

## Map Transfers

- Map downloads are now published to the UI atomically after all perimeter, exclusion, dockpoint, Search Wire, and waypoint phases have completed.
- Each transfer uses an ID and explicit completion message, preventing delayed chunks from an older map from being mixed into the current map.
- Failed phase resets can be retried without exposing incomplete map data.
- Removed the map echo after edit synchronization, eliminating a WebSocket update loop between browser and backend.
- Added a blocking map-loading overlay with an initial spinner followed by cumulative point progress and the currently transferred map area.

## Bug Fixes

- Fixed imported maps being mirrored on the Y axis.
- Fixed map switching being interpreted as map creation when frontend and backend operation values differed.
- Fixed partial map rendering while chunks were still arriving.
- Fixed stale transfer chunks overwriting data from a newer map load.
- Fixed incomplete mowing-settings requests resetting omitted Area, Border, or Exclusion Border options.
- Improved Save/Discard controls when settings data is absent or still loading.

## Upgrade Notes

- Existing SPIFFS maps remain compatible; no migration is required.
- Editing no longer writes a map to SPIFFS automatically. Use **Save** to persist a RAM draft, or **Revert** to restore the last saved version.
- Unsaved drafts are held in backend RAM and therefore do not survive a modem restart.
