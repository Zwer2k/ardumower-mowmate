# Release Notes v1.9.0

This release makes mower firmware uploads work again, stops the modem from mixing up answers between CaSSAndRA and its own status polls, and makes map management safe: no more lost or half-written maps, and every failed operation is reported. It also warns before uploading a map too large for the mower, calculates waypoints faster, draws the mowing map on the live map and redesigns the status dashboard.

## Firmware Upload

- Mower firmware uploads work again. They failed with "Upload request failed" and the modem restarted (last reset: `task-wdt`). The modem wrote every piece of the upload to its flash storage while receiving it, and the storage sometimes blocked for seconds while it cleaned up. The modem now keeps the firmware in PSRAM and flashes the mower directly from there, as it already did for its own firmware. Modems without PSRAM (classic ESP32) still use the flash storage.
- New mower capability **Mower firmware upload**. When off, the firmware dialog offers only the modem firmware and the modem rejects mower firmware uploads. Useful for mowers without the STM32 boot lines, such as the ArduMower PCB 1.3 / 1.4.

## Mower Communication

- CaSSAndRA and other clients connected through the modem no longer get answers meant for the modem's own status polls. The modem sent its polls without waiting for the answer, so a client's next command received the wrong line. CaSSAndRA then repeated its command every second, and Sunray printed `absolutePosSource=0 lon=0.00000000 lat=0.00000000` over and over.
- Commands sent while the connection to the mower is busy are queued instead of dropped. A Stop, Start or Dock from the web interface could get lost silently before.

## Map Upload to the Mower

- Before an upload, the modem estimates from the mower's free memory whether the map fits. The map status shows the points next to the estimated limit, in red when the map is too large, and both upload buttons ask before uploading it. Sunray otherwise stops such an upload with "setPoint: OUT OF MEMORY" and switches to an error. On a MOW800 board with about 19.6 KB free memory the limit is roughly 1800 points.
- When the mower stops accepting map points during an upload (usually out of memory), the modem cancels right away instead of retrying, and the browser shows the reason with the point where it stopped. Sunray itself refused every further upload after an out-of-memory error until it was restarted; that is fixed in Sunray (branch `fix/map-upload-oom-recovery`).
- The "not synced — upload" button in the map editor starts the upload reliably. It resent the whole map first and waited for the modem's confirmation; when that got lost, nothing happened. It now uploads directly when the editor has nothing left to sync, and reports an error instead of retrying forever.
- Saving, calculating and uploading report when the modem does not respond, instead of hiding the progress indicator silently after 30 seconds.

## Map Management

- A scheduled start no longer replaces the current map with a "Map N" copy. The modem took its own upload to the mower for a map uploaded by another program.
- A broken map transfer from another program no longer leaves a half map behind that Save, Upload and Export would then use.
- Saving, renaming and deleting leave the map list intact when the storage is full or a write fails. Before, maps that could not be loaded appeared in the list, or a map vanished after a restart.
- Every map operation reports when it fails: create, copy, load, save, rename, delete, discard, default map and import. Before, failures were silent, and a failed save could even clear the unsaved mark.
- New, Copy, Discard and Import work while a map is being transferred to the browser. "Discard, then New map" always failed silently.
- Import creates its own map with a unique name. It reused the current map's name, was rejected, and still put the imported map and mow settings on the current map.
- Map names are compared without regard to upper and lower case, as on the modem.
- Renaming only updates the map index instead of rewriting the whole map file.
- Deleting the current map switches to the default map, with its saved changes.
- Scheduled mowing follows a renamed map. Entries of a deleted map are disabled, and the delete dialog lists them.
- The map list is sorted by name, marks the map that is on the mower and shows the date a map was last saved. Maps saved with earlier versions show a date after their next save.
- The default-map star is disabled for unsaved maps.
- Switching a mow area toggle no longer transfers the whole map to the browser again. The toggle only changes the mow settings, but the modem marked the map as changed and resent all waypoints with the loading overlay.
- Map transfers between modem and browser send larger batches, and editing a large map no longer resends all waypoints with every change.

## Waypoint Calculation

- Waypoints are calculated faster. The check whether a connection between two mowing lines stays free of exclusions ran tens of thousands of times per calculation, allocated memory each time and tested every edge of the area with double-precision math, which the ESP32-S3 can only emulate in software. It now reuses its memory and skips edges far away from the connection with a quick single-precision check. On a PC this saves about a third of the time with the same routes; the gain on the modem is expected to be larger. The calculated routes are unchanged.

## Live Map

- The live map draws the mowing map on the OpenStreetMap background: perimeter, exclusions, docking path and, optionally, the route. **Map** and **Route** in the toolbar switch them on and off.
- New buttons **Mower position** and **Map position** center the view on the mower or show the whole mowing map. On opening, the live map shows the mowing map.
- The live map can zoom in further (up to level 22), so a small garden fills the screen.
- The map is placed with the reference longitude/latitude from the Position settings (mode Absolute). In mode Relative, the live map derives the reference from the mower's GPS position with an RTK fix and its map position, and shows "Map ref: GPS".
- Without a GPS position, the mower marker is placed via the map reference again. The live map read the reference from a setting that did not exist, so the marker never appeared that way, and its heading was off.

## User Interface

- The status dashboard has the style of the main dashboard: a summary strip with colored status tags and cards for mower, battery, position & GPS, mowing statistics, faults & recoveries, mower controller, modem and sensors. Durations show as hours and minutes, a bar shows how much of the mowing time had a GPS fix, and the new modem card shows firmware, uptime, last reset, WiFi signal, channel, IP, transmit power and memory use.

## Documentation

- New wiring page for the ArduMower PCB 1.3 / 1.4 (`docs/pinout-pcb.md`) with the ESP32-S3 wiring plan, connections and jumper settings. The MOW800 page is now `docs/pinout-mow800.md`.

## Upgrade Notes

- To get mower firmware uploads working, the modem itself needs this release first. If its web upload fails too, install it over USB.
- Maps saved with earlier versions keep working; the map list shows their date after the next save.
- Sunray should run the `fix/map-upload-oom-recovery` change so that uploads work again after an out-of-memory error without restarting the mower.
