# Release Notes v2.6.0

This release focuses on stability under load, especially during mowing, by reducing heap fragmentation on the ESP32-S3 and improving WebSocket reliability.

## Stability & Memory Usage

- **Reduced dynamic allocations in serial/BLE path**: switched `Reader::update()`, `Router` drain callbacks, `MowerAdapter` response/command parsers, `Terminal`, `CLI`, `Console`, and BLE to `const char*` APIs. This removes the temporary `String` allocation for every received line.
- **Fixed-size buffers for command responses**: replaced `String _pendingCommand.response` and the `_cachedRawState` / `_cachedRawStats` / `_cachedRawSensorSummary` / `_cachedRawGpsDetails` caches with fixed `char[READER_BUF_SIZE]` buffers, eliminating repeated re-allocations of state/stats/sensor/gps responses.
- **Map upload response buffering**: converted `MapUploadState.lastResponse` from `String` to a fixed char buffer and updated response helpers to pointer-based parsing.
- **Rotated AT command polling**: the main loop now cycles through state/stats/sensor/gps requests one per iteration and throttles `AT+S3`/`AT+S4` to avoid saturating the serial link.
- **WebSocket stability**: under mowing load the modem now stays responsive significantly longer. In field tests the WebSocket connection was observed to be much more stable than in previous versions.

## Obstacle Detection

- Added `Obstacles` domain type and WebSocket response type for mower-detected obstacle polygons.
- Polls obstacles via `AT+S2` every 5 seconds.
- Forwards obstacle polygons to connected WebSocket clients.
- Renders detected obstacles as orange filled polygons on the map and on the dashboard MiniMap.

## UI

- **Default dashboard**: after boot the UI now redirects from `/` to `/?dashboard=main` so the main dashboard is shown by default instead of the settings page.
- **Obstacles on dashboard map**: detected obstacles are now rendered on the main dashboard MiniMap in addition to the map page.
- **Goto visibility**: fixed the Goto overlay so it remains visible even when the map is not yet synchronized with the mower.
- **WebSocket protocol**: automatically uses `wss://` when the page is served over HTTPS.

## Backend

- **Position mode applied after handshake**: `applyPositionSettings()` is now sent after the first successful version exchange (`parseVersionResponse`) instead of during `begin()`, ensuring the mower is ready to receive `AT+P`. It is also re-applied after saving position settings via the HTTP API.
- **HTTP command buffering**: simplified request body buffering for incoming command requests.
- **Live map**: removed the mower-reference position fallback in the live map so it relies on GPS PVT data.
