# Release Notes v1.7.0

This release makes routes on maps with many exclusions safe: connection lines no longer cut through exclusions or leave the perimeter. It also stops the modem from restarting after a waypoint calculation, shows the calculation progress in percent, imports CaSSAndRA maps that were exported without a reference position, and makes WiFi much faster when Bluetooth is not used.

## Route Planning

- Connection lines stay inside the perimeter and outside every exclusion. On maps with many exclusions they cut straight through exclusions and across bays outside the perimeter. This affected the connections inside the mowing pattern, the transitions between border laps, and the connection from the border laps to the pattern.
- Connections now follow the shortest free path around exclusions and perimeter corners and keep 3 cm away from exclusion edges. Inside the mowing pattern they stay within the mowing area first, so the configured distance to border is kept.
- The final route check covers exclusions too. Before, it only checked the perimeter.
- Route simplification no longer removes the corner points of a detour, which turned a correct detour back into a straight line through an exclusion.
- The calculation shows its progress in percent, followed by "Sending route" at 96 %. Before, the progress bar stayed at 0 % until the calculation finished.

## Stability

- The modem no longer restarts after calculating waypoints. Its internal RAM ran out (as little as 528 bytes free) because the framework only placed blocks of 4 KB and larger in PSRAM, while the 8 MB PSRAM stayed almost unused. Blocks of 512 bytes and larger now go to PSRAM, and during the calculation almost everything does.
- Messages to the browser are no longer dropped for lack of memory when they fit in PSRAM. Large messages are checked against PSRAM instead of internal RAM.
- The restart on a fragmented heap waits until the condition has lasted 10 seconds. Short drops, for example while a large map is sent to the browser, no longer restart the modem.
- After a restart, the log shows why it happened: the reset reason (power-on, software, crash, watchdog, brownout), the cause of a deliberate restart with heap values, the operation that was running, and the last waypoint calculation. The heartbeat repeats the reset reason and now includes free PSRAM.

## WiFi

- With Bluetooth disabled, WiFi power save is turned off in client (STA) mode. Measured on an ESP32-S3: ping dropped from 191 ms to 32 ms on average, and downloads went from 6–9 KB/s to 290–570 KB/s. Firmware uploads and map transfers are correspondingly faster.
- After connecting, the log shows signal strength, channel and power save state.

## Map Import

- CaSSAndRA GeoJSON files exported without a configured reference position can be imported. CaSSAndRA then writes small degree offsets around 0,0 instead of real coordinates, and the import rejected them against the modem's reference position.
- In Relative position mode, GeoJSON import and export ignore the hidden reference longitude/latitude and use 0,0. A file with real WGS84 coordinates shows a hint to switch to Absolute mode.
- The import dialog has a file picker and detects whether a file is CaSSAndRA GeoJSON or Grauonline JSON.

## Map Editor

- The point counts start with Total, followed by area, perimeter, dock, way and sync state. The exclusions come last.
- From 10 exclusions on, the exclusion list scrolls and keeps the selected exclusion in view.

## Upgrade Notes

- Disable Bluetooth in the modem settings if you do not use it, then restart the modem. ESP-IDF requires WiFi power save while Bluetooth is enabled, so the WiFi speedup only applies without Bluetooth.
- Recalculate the waypoints of maps with exclusions and upload them to the mower. Routes calculated with earlier versions may still contain lines through exclusions.
- The waypoint calculation takes slightly longer than before because every connection is checked against the exclusions.
