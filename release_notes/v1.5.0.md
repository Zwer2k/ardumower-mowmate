# Release Notes v1.5.0

This release moves the firmware update check onto the modem, adds a route quality check after waypoint calculation, and brings undo/redo and keyboard editing to the map editor. It also fixes several map storage and scheduling defects that could silently lose edits.

## Firmware Updates

- The modem now checks GitHub for new releases itself, in the background: once 60 seconds after it becomes operational and every 6 hours after that. The browser no longer contacts GitHub at all.
- A new info icon appears in the header next to the remote control as soon as a newer stable release exists, and opens the firmware dialog.
- The version list in the dialog comes from the modem and keeps the 10 newest installable releases — stable `vX.Y.Z` tags that carry a firmware asset for the connected board.
- GitHub is offered as an update source only after the modem has confirmed it reached GitHub. Before that the dialog reports that a check is running instead of claiming GitHub is unreachable.
- Blocked checks name their reason — no WiFi, unsynchronized clock, or a running update — instead of reporting a generic failure, and are retried every 60 seconds.
- Fixed the release list arriving empty: `HTTPClient::getStream()` hands out the raw socket, so a chunked response carries its chunk lengths inside the JSON. The parser read the first length as a number, discarded it against the filter and reported an empty document without an error. Chunked responses are now decoded before parsing.
- Firmware status travels over the existing UI WebSocket (`requestFirmwareStatus` / `firmwareStatus`) instead of a separate REST endpoint and polling loop.
- Added debug logging for the whole check: scheduling, DNS, HTTP response, transfer encoding, one line per examined release with the reason it was accepted or skipped, and the resulting selection.

## Route Check

- After every waypoint calculation the modem runs a quality check over the finished route and reports length, waypoint count, rotations on the spot, steered corners and estimated mowing time.
- Findings cover corners the line tracker cannot follow cleanly, adjacent overlapping corners and zero-length segments. The thresholds mirror Sunray's line tracker, so the report matches what the mower will actually do.
- The check never modifies the route and never blocks an upload.
- Findings in the report are clickable: selecting one marks the waypoint on the map and, with the editor open, selects it for correction right away.
- Two new per-map settings drive it: a route simplification threshold that removes nearly collinear waypoints, and a minimum turn radius used only for the report.

## Map Editor

- Added undo/redo with a 50-step history. A snapshot is taken once per finished gesture, so dragging a point across the canvas is a single undo step.
- Added keyboard editing: Del removes the selected point, Escape cancels draw mode or clears the selection, Ctrl+Z and Ctrl+Y undo and redo. Text inputs are excluded.
- Incoming map transfers no longer overwrite the editor state. Previously every debounced edit made the backend broadcast the map back, reverting edits made in the meantime.
- Editing waypoints now works on the full list instead of the list filtered by the mow-area toggles, which previously dropped hidden points on a drag and misapplied filtered indices.
- Hit areas follow the pointer actually in use rather than the device's touch capability, so mouse users on touch-capable laptops no longer select points from far away. Touch targets are a constant size on screen at every zoom level.
- On overlapping elements the nearest one is selected instead of the one drawn last, which previously made short edges unselectable under endpoint hit circles.
- The compass reacts to pointer events, so the map can be rotated on touch devices.
- Dragging a point keeps its metadata (delta, sol, timestamp, and for waypoints the planner tag and connector flag the mow-area toggles depend on).
- The "unsaved changes" dialog has a Cancel button; closing it with Escape or X no longer discards the changes.
- Maps with unsaved changes are marked in the dropdown, and the sync indicator in the overlay triggers the upload.
- Rejected map syncs are retried instead of being lost when the backend was streaming to clients.

## Map Storage and Scheduling

- Saving a new map no longer writes into an existing map with the same geometry hash. "Copy" followed by "Save" created a rename instead of a second map.
- Deleting the default map falls back to the first remaining map immediately, instead of leaving no active map until the next reboot.
- Deleting the loaded map picks up the replacement's CRC and mow settings and clears the deleted map's draft state.
- Scheduled runs use the stored map instead of the RAM draft, so a scheduled run can no longer mow with unsaved edits, and no longer switch the map underneath an open editor.
- Queueing an upload resets the transfer phase, so the scheduler can no longer start mowing on the previous upload's success report.
- Border settings (`distanceToBorder`, `borderLaps`, `mowBorderCcw`) are serialized to SPIFFS. They were never written and fell back to defaults on load.
- `distanceToBorder` counts track widths, not metres. The dialog is labelled accordingly, steps in whole numbers and defaults to 1; the previous default of 0.3 was truncated to 0 and disabled the offset it was meant to enable.
- A schedule entry can no longer be created for a map that was never saved.
- The map hash is computed when it is needed instead of on every edit, which previously ran an MD5 over the serialized geometry several times per second while dragging.

## Logging

- Every log line reaches the browser. The modem streamed only the last six lines per update and at most once per 100 ms, so anything above 60 lines/s was dropped silently.
- Missing ranges are marked in the log view where they actually occur. The previous marker followed the scroll position rather than the data.
- Locally trimmed lines are reported above the list.

## Connection Stability

- Upgraded ESPAsyncWebServer to 3.12.1 with AsyncTCP 3.5.0. Version 3.11.1 tore WebSocket frames when the payload did not fit the TCP send window, which made browsers report a UTF-8 or frame header error and drop the connection, typically right after connect.
- `sanitizeUtf8InPlace()` returns without allocating when the string is plain ASCII, which is the case for all serialized JSON.

## Dashboard

- The mowing time is shown in the unit it is labelled with. The mower reports seconds; the tile divided by 60 and labelled the result "h", showing minutes under an hours label. Below an hour it now shows whole minutes, above it hours with one decimal.

## Build

- Reduced the classic ESP32 image by 34 KB by disabling Arduino core logging on that target. Free flash grows from 65 KB to 100 KB. Panic backtraces and the modem's own log are unaffected; the ESP32-S3 keeps core logging at INFO.
- Removed the unused `AUnit` and `ArduinoWebsockets` dependencies and a redundant `-Og` override from the classic ESP32 environment. The hardware test build uses `arduino-cli` with its own library list and is unaffected.
- Path planner tests build into `test_pathplanner/build/` and are no longer tracked; four test binaries of about 300 KB each had slipped into the repository.

## Upgrade Notes

- Maps saved before this release lost their border settings. They come back as one track width and one lap and need to be set once more.
- The firmware check requires internet access and a synchronized system clock on the ESP, because the GitHub certificate cannot be validated otherwise. Until the clock is set, the dialog reports this instead of offering GitHub.
- Whether an update exists is now decided by the modem alone. A browser without internet access no longer affects the update indicator or the version list.
- Debug logging for the firmware check is available at the DBG modem log level and costs nothing at INFO.
